# 不同大模型架构
# Qwen Family

### 1) 系列与规模（Dense + MoE）
- **Dense（稠密）**：0.6B / 1.7B / 4B / 8B / 14B / 32B  
- **MoE（混合专家）**：30B-A3B、235B-A22B  
  - 旗舰 **235B 总参数，约 22B 激活参数/Token**

---

### 2) 基本骨架（Dense：Decoder-only Transformer）
Qwen3 的 Dense 架构整体延续 Qwen2.5 的“现代 Transformer”组合：
- **Attention：GQA（Grouped-Query Attention）**
- **位置编码：RoPE**
- **FFN：SwiGLU**
- **归一化：RMSNorm + Pre-Norm**

相对上一代/早期设计的关键改动（更偏“训练稳定性”）：
- **移除 QKV bias**
- 在注意力里加入 **QK-Norm**，用于更稳定训练

---

### 3) MoE 结构要点（Qwen3-MoE）
MoE 部分强调“更细的专家分工 + 更高性价比”：
- **每层 128 个专家（total experts）**
- **每个 token 路由激活 8 个专家（top-8）**
- **不使用 shared expert**（和一些 MoE 设计不同）
- **fine-grained expert segmentation**（更细粒度专家切分）
- **global-batch load balancing loss**：鼓励专家负载更均衡、能力更专精

---

### 4) Tokenizer
- 使用 **BBPE（byte-level BPE）**
- 词表大小 **151,669**

---

### 5) 上下文长度与长上下文能力
#### 5.1 各模型上下文长度（官方表格口径）
- 0.6B / 1.7B：**32K**
- 4B / 8B / 14B / 32B：**128K**
- MoE 两个模型：**128K**


#### 5.2 长上下文训练与推理期扩展（可当亮点说）
- 预训练分三阶段，最后一阶段用 **32,768** 的序列长度做长上下文训练
- 为 RoPE 外推把 base frequency 从 **10,000 提到 1,000,000（ABF technique）**
- 推理期引入 **YaRN + Dual Chunk Attention (DCA)**，提升长序列推理容量（报告里描述为约 4× 容量）

---

### 6) “Hybrid Thinking” 是 Qwen3 的核心卖点
Qwen3 把两种工作方式做进同一个模型：
- **Thinking mode**：先分步推理，再给答案（适合难题）
- **Non-thinking mode**：更快给答案（适合简单题/低延迟场景）

两套控制方式（面试时说清楚很加分）：
1) **硬开关（hard switch）**：推理模板层面控制  
   - 例如 chat template 里 `enable_thinking=False` 可以直接关闭推理输出
2) **软开关（soft switch）**：对话中逐轮切换  
   - 在 prompt 或 system message 里加入 **/think** 或 **/no_think**，按“最近一次指令”生效

---

### 7) Thinking Budget（推理预算控制）
Qwen3 支持“推理 token 预算”：
- 思路：当推理 token 达到预算后，用“early-stopping prompt”结束推理段，并引导模型直接输出总结/答案
- 文档也给了一个常见工程实现：**生成两次**
  1) 先生成到 budget，看推理是否结束
  2) 如果没结束，拼接 early-stopping prompt，再继续生成最终答案

---

### 8) 训练数据与训练流程（为什么它会强）
- 预训练数据规模：**36T tokens**，覆盖 **119 种语言/方言**
- 数据构建上用到“模型辅助数据扩展”：
  - 用视觉语言模型从大量 PDF-like 文档中抽取文本，再用语言模型做质量提升
  - 用专用模型合成数学/代码/教材/QA 等数据
- 预训练三阶段：
  - **S1（通用）**：>30T tokens，4K context
  - **S2（推理增强）**：~5T 更高质量 tokens，提升 STEM/代码/推理数据占比
  - **S3（长上下文）**：数千亿 tokens，32K 训练长度

# Llama Family
Llama 系列一直坚持 **decoder-only Transformer** 这条主线，通过更“省算力”的结构细节、更多更干净的数据、更长上下文、以及对齐与安全工具链，把开源生态的可用性做到了第一梯队。

---

## 1. 核心架构主干（家族共同点）
- **模型类型**：自回归（auto-regressive）的 **decoder-only Transformer**。
- **关键结构习惯**（从 LLaMA 1 开始就奠定）：
  - **Pre-Norm + RMSNorm**：把归一化放在子层输入处，提升训练稳定性。
  - **SwiGLU FFN**：替换 ReLU 系列激活，常见收益是更好的效果/算力比。
  - **RoPE 旋转位置编码**：用旋转位置编码替代绝对位置嵌入，长上下文扩展更友好。
- **对齐范式**：指令模型一般走 **SFT + RLHF**（后续 3.x 里反复出现）。

---

## 2. 代际演进与创新点（按时间线）

### 2.1 LLaMA / Llama 1（2023）
**定位**：把“更小但更强”的开源基座模型推到主舞台，强调推理效率（inference budget）和公开数据训练。  
**结构亮点**：
- Pre-Norm（RMSNorm）、SwiGLU、RoPE 三件套成为 Llama 风格的“底座配置”。  
**工程/训练亮点**：
- 重点强调训练与推理效率优化（例如更高效的注意力实现、checkpointing、手写 backward 等思路）。

---

### 2.2 Llama 2（2023）
**定位**：在保持 Llama 1 主干架构的前提下，把“能用的 Chat”做出来，并提升上下文与推理效率。  
**关键变化**：
- **更多预训练 token**、**上下文长度翻倍到 4096**。
- **70B 引入 GQA（Grouped-Query Attention）**：降低 KV cache 压力，提高推理效率与可扩展性。
- Chat 模型强调对齐与安全评测，生态可落地性明显提升。

---

### 2.3 Llama 3（2024）
**定位**：开源生态里“强基座 + 强指令”的关键一代（8B/70B）。  
**关键变化**：
- **Tokenizer 升级到 128K 词表**：提升编码效率与覆盖面（尤其对代码/符号/多语种片段更友好）。
- **训练序列长度 8192（8k）**，并且 **全系使用 GQA** 来提升推理效率。
- **预训练数据量提升到 15T+ tokens**；指令模型继续 **SFT + RLHF** 对齐路线。
- 给出明确 **知识截止时间**（不同大小略有差异），面试时可强调“数据新鲜度管理”。

---

### 2.4 Llama 3.1（2024）
**定位**：把 Llama 3 推到“可做更复杂任务/更长上下文/更强多语”的版本，并加入超大模型。  
**关键变化**：
- **模型规模扩展到 8B/70B/405B**。
- **上下文长度直接拉到 128K**（长文档、检索增强、工具调用更实用）。
- **多语输入/输出**（官方列出 8 种重点支持语言），并强调可以用于蒸馏、合成数据等用途。
- 指令微调数据里明确提到 **大量合成样本（25M+）**，体现“数据工程 + 对齐工程”的路线。

---

### 2.5 Llama 3.2（2024）
**定位**：两条线同时推进——**端侧轻量化** 与 **多模态（视觉）**。  
**关键变化**：
- **轻量文本模型（1B/3B）**：面向边缘设备/移动端部署（生态意义很大）。
- **Vision 模型（11B/90B）**：支持 *text+image 输入 / text 输出*，用于图像理解、视觉推理、caption、VQA 等。
- 官方生态与云厂商集成强调：视觉版本采用“把图像编码器表示注入语言模型”的集成式架构思路（面试时可用作多模态设计的通用表述）。

---

### 2.6 Llama 3.3（2024）
**定位**：继续在 **70B text-only instruct** 这个“高性价比档位”上迭代能力。  
**关键变化**：
- 仍是 **128K 上下文**、**GQA**、多语能力维持。
- 多家平台发布说明强调：相对 3.1 70B，在推理、数学、代码、指令遵循等能力上有提升（强调“同尺寸更强”）。

---

## 3. 面试可直接复用的“亮点回答句式”
- “Llama 的主线是 decoder-only Transformer，但通过 **RMSNorm + SwiGLU + RoPE** 这些细节，把训练稳定性和效果/算力比打牢。”
- “推理侧的标志性设计是 **GQA**：它用更少的 KV heads 服务更多 query heads，主要收益是 **更省显存、更快推理、KV cache 更友好**。”
- “3 代最大的工程变化之一是 **tokenizer 128K** 和 **15T+ 预训练 tokens**，属于‘结构不激进，但数据与工程极激进’。”
- “3.1 把上下文拉到 **128K**，让检索增强、长文档总结、工具调用这类场景更实用。”
- “3.2 的关键是产品化路线：一边做 **端侧 1B/3B**，一边补齐 **视觉多模态 11B/90B**。”

---

## 4. 常见追问速答（简短版）
- **为什么 GQA 有用**：减少 KV cache 规模与带宽压力，推理吞吐更好，尤其大模型更明显。
- **RoPE 的价值**：相对绝对位置嵌入，更利于长上下文外推/扩展（工程上也更常见）。
- **128K 上下文怎么“成立”**：通常是训练与推理策略共同设计（数据、位置编码/缩放、注意力与缓存工程），Llama 3.1 直接把它作为模型规格给出。
- **Llama 的“创新点”是不是结构发明**：更多是“成熟结构 + 极强数据工程/训练工程/推理工程 + 生态发布策略”的组合拳。

2. Mistral Family
# Kimi Family
Kimi 是 Moonshot AI 的模型/产品线，主打 **超长上下文 + Agent（工具调用）+ 强工程训练**。近一年最核心的“代表作”是 **Kimi K2（开源权重）**，以及面向多步推理与工具编排的 **Kimi K2 Thinking**。

---

## 1) Kimi K2（开源权重 MoE 基座/指令）
### 1.1 核心架构
- **模型类型**：MoE Transformer（超稀疏 MoE）
- **规模**：约 **1.04T 总参数**，每 token **~32B 激活参数**
- **层数**：61
- **注意力机制**：**MLA（Multi-head Latent Attention）**（设计上“类似 DeepSeek-V3 风格”）
- **MoE 配置**：
  - **总专家数 384**
  - **每 token 激活 8 个专家**
  - 采用 **sparsity=48**（384/8）

### 1.2 关键训练/工程创新（为什么它“很能跑”）
- **MuonClip 优化器**：在 token-efficient 的 Muon 之上加入 **QK-Clip**，用来解决训练不稳定（注意力 logits 爆炸）问题  
- **QK-Clip 的直觉**：当某些 head 的 attention logits 过大，就按 head 级别对 **Wq/Wk** 做缩放，尽量“只干预问题 head”，减少副作用  
- **预训练数据规模**：**15.5T tokens**（Web/Code/Math/Knowledge 四大类）
- **Agentic 后训练**：
  - **大规模 agentic 数据合成**：系统化生成工具、任务、轨迹（含模拟环境与真实环境）
  - **通用 RL 框架**：把 **可验证奖励（RLVR）** 和 **self-critique rubric** 结合，让模型学会自评与纠错  
- **评测口径强调**：文中大量结果以 **non-thinking（不长思维链）** 的设置对比

---

## 2) Kimi K2 Thinking（“会思考 + 会用工具”的版本）
### 2.1 产品化特征（面试官很爱追问）
- 目标是 **thinking agent**：边推理边调用工具（tool calling / function calling）
- 强调 **长时序工具使用稳定性**：能连续进行很多轮工具调用而不崩（官方材料强调 200–300 步量级）
- 同时做了 **原生 INT4（量化感知训练/QAT）**，用更低显存/更快推理来落地长上下文

---

## 3) Kimi k1.5（强化学习 + 长 CoT 的训练系统代表作）
> 注意：k1.5 更像“训练系统与方法论”的代表作，K2 更像“开源权重与 agentic 落地”的代表作。

### 3.1 核心创新点（讲清楚就很加分）
- **Long context scaling in RL**：把 RL 训练的上下文扩到 **128K**，并观察到“上下文更长 → 推理更强”的持续收益  
- **Partial rollouts**：复用之前轨迹的一大段来采样新轨迹，减少重新生成的成本，提高 RL 训练效率  
- **改进的 policy optimization**：用在线 mirror descent 风格的稳健优化，并配合采样策略、长度惩罚、数据配方优化  
- 结果是：不依赖 MCTS / value function / 过程奖励模型等复杂组件，也能做出很强的长 CoT 学习效果  
- **多模态**：联合训练文本与视觉数据，支持跨模态推理

---

## 4) Kimi-VL / Kimi-VL-Thinking（多模态结构创新点）
### 4.1 模型结构（三段式，清晰好背）
- **MoonViT（视觉编码器）**：原生支持不同分辨率输入（native-resolution），用 patch packing，把图像当“可变长序列”处理
- **MLP Projector**：两层 MLP（含像素 shuffle 下采样）把视觉特征投影到 LLM embedding 维度
- **MoE 语言模型（Moonlight）**：MoE decoder；文中给出的 Moonlight 规格是 **2.8B 激活 / 16B 总参**，并用 8K 上下文的中间 checkpoint 初始化

### 4.2 关键点（你可以当“它和一般 VLM 不一样”来讲）
- 视觉侧引入 **2D RoPE** 来加强高分辨率下的空间位置表达  
- **Kimi-VL-Thinking**：在 long-CoT 激活与 RL 后，强化更复杂的多模态推理能力（偏“难题更会想”）

---

## 5) 面试可直接背的 5 句话（精简版）
1. Kimi 的代表作 K2 是 **超稀疏 MoE**：**1.04T 总参，~32B 激活**，走的是“算力更省但不掉点”的路线。  
2. K2 的注意力用 **MLA**，MoE 做到 **384 专家、top-8 激活**，并用 sparsity scaling law 选了 **sparsity=48**。  
3. 训练侧的标志是 **MuonClip + QK-Clip**：解决 attention logits 爆炸，让 15.5T 级别预训练更稳定。  
4. 后训练突出 **agentic 数据合成 + RL（含 RLVR 与自评 rubric）**，目标是更强工具使用与多步任务完成。  
5. K2 Thinking 进一步把模型做成 **thinking agent**，并给到 **256K 上下文 + 原生 INT4**，强调长时序工具调用稳定性。

# GPT-OSS
gpt-oss-120b / gpt-oss-20b 是 OpenAI 发布的**开源权重**（Apache 2.0）**推理型 MoE（Mixture-of-Experts）自回归 Transformer**，面向 **agentic 工作流**（工具调用、强指令遵循、结构化输出），并提供**可调推理强度**与**完整 CoT**。

---

## 1) 模型家族与关键规格（最常被问）
### gpt-oss-120b
- **层数**：36
- **总参数**：116.8B（文中简称 120b）
- **每 token 激活参数（active params）**：5.1B
- **专家数**：每个 MoE block **128 experts**
- **路由**：每 token **Top-4 experts**
- **checkpoint 大小**：60.8 GiB

### gpt-oss-20b
- **层数**：24
- **总参数**：20.9B（文中简称 20b）
- **每 token 激活参数（active params）**：3.6B
- **专家数**：每个 MoE block **32 experts**
- **路由**：每 token **Top-4 experts**
- **checkpoint 大小**：12.8 GiB

> 面试讲法：总参很大，但每步只激活少量专家，所以推理成本更接近“激活参数规模”。

---

## 2) 量化与部署创新（工程亮点）
- **对 MoE 权重做后训练量化到 MXFP4**（约 **4.25 bits/param**）。
- MoE 权重占总参数 **90%+**，因此量化收益非常大：
  - 让 120b 能放进 **单张 80GB GPU**
  - 让 20b 能在 **16GB 内存**级别系统上运行

---

## 3) 基本架构（Transformer + MoE）
### 3.1 Residual / Norm 习惯
- **Residual stream 维度**：2880
- 每个 attention 与 MoE block **之前**做 **RMSNorm**
- **Pre-LN**（类似 GPT-2 的层归一化放置）

### 3.2 MoE（路由与 FFN）
- 每个 MoE block：固定数量 experts（120b: 128；20b: 32）+ 线性 router
- 每个 token 选 **Top-4** experts
- 只在被选中的 experts 上做 softmax 归一化，再加权汇合输出
- FFN 使用 **gated SwiGLU**
  - 文中特别说明：他们的 SwiGLU 实现“有点不一样”，包含 **clamping** 与 **残差连接**

---

## 4) 注意力与长上下文（容易被追问）
### 4.1 注意力形态
- 参考 GPT-3：attention 层在两种 pattern 间交替：
  - **banded window（局部带状）**
  - **fully dense（全局稠密）**
- **局部带宽**：128 tokens

### 4.2 Heads 与 GQA
- 每层 **64 个 query heads**，每个 head 维度 64
- 使用 **GQA**：**8 个 key-value heads**

### 4.3 位置编码与 128K
- 使用 **RoPE**
- 通过 **YaRN** 把（稠密层的）上下文长度扩到 **131,072（≈128K）**

### 4.4 “可忽略所有 token”的 attention（很特别的小点）
- 每个 attention head 在 softmax 分母里加入一个 **learned bias**
- 作用：让注意力机制在需要时可以“对任何 token 都不关注”（文中类比 off-by-one attention / attention sinks）

---

## 5) Tokenizer 与 Harmony Chat Format（agent 能力关键）
### 5.1 Tokenizer
- 全训练阶段使用 **o200k_harmony tokenizer**
- 属于 **BPE**，并扩展自更通用的 o200k 系列
- **词表大小：201,088**
- tokenizer 显式包含支持 harmony 格式的一些特殊 token

### 5.2 Harmony Chat Format（“必须按这个格式用”）
- 用特殊 token 明确**消息边界**
- 用关键字参数标注作者/接收者（如 User / Assistant）
- 角色体系与 OpenAI API 一致：System / Developer / User / Assistant / Tool
- 明确的指令优先级（用于冲突消解）：
  - **System > Developer > User > Assistant > Tool**
- 还引入 channels：
  - **analysis**：CoT 推理 token
  - **commentary**：函数/工具调用相关
  - **final**：最终给用户展示的答案
- 多轮对话实践建议：不要把上一轮 assistant 的推理轨迹原样留在上下文里（避免干扰后续）

---

## 6) 训练数据与训练栈（你可以用来回答“为什么强/为什么稳”）
### 6.1 预训练数据（方向与安全过滤）
- 文中描述为：**trillions of tokens** 的纯文本数据
- 重点：**STEM、coding、general knowledge**
- 预训练阶段做了安全过滤，特别是**危险生物安全相关**内容：复用 CBRN 过滤器体系
- **知识截止时间：June 2024**

### 6.2 训练工程栈
- 用 **NVIDIA H100**、**PyTorch**
- 使用 **expert-optimized Triton kernels**
- 用 **FlashAttention** 降显存并加速训练
- 训练成本量级（文中给了具体数字）：
  - 120b：约 **2.1 million H100-hours**
  - 20b：大约少一个数量级（接近 10x 更少）

---

## 7) 后训练：推理与工具使用（最像“产品能力”的部分）
### 7.1 CoT + RL（推理能力）
- 后训练使用与 OpenAI o 系列相似的 **CoT 强化学习技术**
- 目标：学会用 CoT 解题，并把这种能力泛化到多类题目（数学、代码、科学等）

### 7.2 Variable Effort Reasoning（可调推理强度）
- 训练出 3 档推理模式：**low / medium / high**
- 通过 system prompt 里插入关键词（例如 `Reasoning: low`）选择模式
- 推理档位越高，模型平均 **CoT 更长**
- 实验现象：推理档位提升带来“平滑的 test-time scaling”，但会显著增加延迟与成本  
  > 面试讲法：这是“可控计算量”的设计，让同一模型在速度/精度之间做开关。

### 7.3 Agentic Tool Use（工具调用能力）
后训练显式教模型用三类工具：
1) **浏览/检索工具**：调用 search/open 与网页交互，提高事实性，也能获取知识截止之后的信息  
2) **Python 工具**：在有状态的 notebook 环境里运行代码  
3) **开发者自定义函数**：Developer 消息里提供 function schema，模型按 harmony 格式完成调用  
并且模型可被配置为“带工具/不带工具”两种运行方式。

## 9) 面试可直接背的 5 句话（高命中）
1. gpt-oss 是开源权重的 **MoE 自回归 Transformer**：120b 总参 116.8B，但每 token 只激活 **5.1B**；20b 激活 **3.6B**。  
2. MoE 路由是 **Top-4**，120b 每层 128 experts、20b 每层 32 experts，并用 gated SwiGLU 做 FFN。  
3. 注意力层在 **局部带状（128 带宽）与全局稠密**之间交替，并用 **GQA（64Q / 8KV）**。  
4. 通过 **YaRN + RoPE** 支持 **131,072（≈128K）**上下文，并加了每 head 的 learned bias 让注意力能“选择不看任何 token”。  
5. 产品化关键是 **harmony chat format + 三档 reasoning（low/med/high）+ 原生工具训练（浏览/Python/函数）**，再配合 **MXFP4** 量化让部署成本落地。  



# DeepSeek
### V3
如果只看 **DeepSeek-V3** 相比前作/常规大模型训练路线里更值得算“创新点”的部分，核心是这 5 个：

* **无辅助损失的 MoE 负载均衡**：论文把这个当成 V3 的一个主要新点。它不再靠传统 auxiliary loss 强行拉平专家负载，而是用 **auxiliary-loss-free** 的方式做负载均衡，目的是减少负载均衡项对主任务建模能力的干扰。给每个专家加一个仅用于路由的 bias，某个专家太忙就把它的 bias 往下调，太闲就往上调。

* **引入多 Token 预测训练目标**：V3 不只预测下一个 token，还加入 **Multi-Token Prediction (MTP)**，让模型在每个位置学习预测多个未来 token。作者认为这能加密训练信号、提升数据效率，还能让模型更早形成“前瞻式”表征；同时它还能被拿去做 speculative decoding，加速推理。

* **首次在超大规模模型上验证 FP8 训练可行**：论文明确声称，V3 设计了一套 **FP8 mixed precision** 训练框架，并“首次”在超大规模模型上验证其有效性。重点不只是低精度本身，而是把 FP8 真正推进到 600B+ 级别模型训练里，同时把损失误差控制在可接受范围。

* **DualPipe 管线并行减少通信瓶颈**：为了解决跨节点 MoE 专家并行带来的高通信开销，V3 设计了一个新的 pipeline parallel 算法 **DualPipe**。它的核心价值是更强的计算-通信重叠，降低 pipeline bubbles，从而提升大规模分布式训练效率。

* **做到无 token dropping 的稳定大规模训练**：很多 MoE 系统为了控负载会丢 token，但 V3 明确强调 **训练和推理都不丢 token**，这依赖前面的负载均衡与部署策略。同时，论文还强调其完整训练过程没有不可恢复的 loss spike，也没有回滚，说明它把“超大规模、高效率、稳定性”同时做到了。

### V3.2
-  **DSA**: a lightning indexer that only give a score between the query and its preceding tokens. Then select the top-k queries.
- **Mix RL training**: Merge reasoning, agent, and human alignment training into one RL stage.
- **Keep Sampling Mask**:  preserves language consistency during RL training due to the top-k/p sampling inconsistency in inference.
- **Keep Routing**: preserve the expert routing paths used during sampling in the inference framework and enforce the same routing paths during training, ensuring that identical expert parameters are optimized.
- **Off-Policy Sequence Masking**: To stabilize training and improve tolerance for off-policy (pre-generated RL rollouts could cause off-policy behavior) updates, we mask negative sequences that introduce significant policy divergence.
- **Thinking in Tool-Use**: reasoning nonagentic data + non-reasoning agentic data + reasoning agentic data

### Deepseek R1
* **纯强化学习直接激发推理能力**：R1-Zero 直接在 base model 上做大规模 RL，**不先做 SFT 冷启动**，论文把这视为首个公开验证“仅靠 RL 也能把推理能力训出来”的结果。

* **长链思维可在奖励驱动下自然涌现**：作者强调，模型在 RL 过程中会自己发展出**长 CoT、自我校验、反思和策略调整**，而不是主要依赖人工写好的推理示范。

* **规则奖励替代复杂神经奖励模型**：R1-Zero 主要用**答案正确性奖励 + 输出格式奖励**，并明确说明没有采用神经 reward model，以减少 reward hacking 风险并简化训练流程。

* **多阶段训练兼顾性能与可读性**：R1 在 R1-Zero 基础上加入**cold-start 数据、两轮 RL、两轮 SFT、rejection sampling**，专门解决 R1-Zero 的可读性差和语言混杂问题。

* **大模型推理能力可蒸馏到小模型**：论文显示，从 R1 蒸馏出的较小 dense 模型效果优于直接在小模型上做 RL，说明大模型学到的推理模式可以有效下放。
